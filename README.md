# Canvesidian — same note, free placement

**همان نوت، همان تب؛ بلاک را بگیر، جابه‌جا کن، همان‌جا بنویس.**

Version **0.2.0** is an experimental proof of concept for spatial placement **inside the existing Markdown editor**. It supersedes the separate-board approach in v0.1. It does not create another note, a Canvas file, or a custom workspace view.

> این نسخه هنوز داخل اپ واقعی Obsidian تست نشده است. موتور واقعی CodeMirror در Chromium تست شده، ولی API میزبان و renderer ابسیدین در تست‌ها mock هستند. قبل از استفاده از vault بک‌آپ بگیرید و ابتدا روی vault آزمایشی امتحان کنید.

## تجربهٔ کار

۱. همان نوت موجود را در **Live Preview** باز کنید.
۲. نشانگر ماوس را روی یک پاراگراف ببرید. دستگیرهٔ `::` کنار آن ظاهر می‌شود.
۳. دستگیره را بکشید و بلاک را هرجای فضای نوت رها کنید. بقیهٔ نوت در ویرایشگر عادی می‌ماند؛ ترتیب Markdown عوض نمی‌شود.
۴. روی متن دوبار کلیک کنید یا `Edit` را بزنید. Markdown **در همان محل** قابل ویرایش می‌شود؛ پنجرهٔ جدا باز نمی‌شود. تغییرات از طریق transaction به سند اصلی می‌روند، نه یک فایل یا کپیِ مستقل.
۵. با `Done`، `Escape` یا `Ctrl/Cmd+Enter` به نمایش رندرشده برگردید. کلیدهای پایان ویرایش حین composition اجرا نمی‌شوند.
۶. بلاک هنگام اسکرول همراه فضای نوت حرکت می‌کند و بعد از بسته‌شدن/بازشدن ویرایشگر، جای آن از دادهٔ ذخیره‌شده بازیابی می‌شود.
۷. `Return` بلاک را به جریان عادی متن برمی‌گرداند؛ متن و ترتیب منبع دست‌نخورده می‌مانند.

اگر دستگیره در تم شما ظاهر نشد، مکان‌نما را داخل بلاک بگذارید و از Command Palette اجرا کنید:

- `Canvesidian: Float this block in the current note`
- `Canvesidian: Show / hide spatial layout in this note`
- `Canvesidian: Recover interrupted block drafts`

فرمان، بلاک را ابتدا در حاشیهٔ خالی یا پایین متن می‌گذارد؛ می‌توانید آن را به محل دلخواه بکشید. خالی‌کردن کامل متن یک بلاک، آن بلاک را از چیدمان خارج می‌کند؛ undo متن، چیدمان حذف‌شده را برنمی‌گرداند.

منوی راست‌کلیک ویرایشگر هم گزینهٔ `Float this block here` دارد. در Source mode، متن اصلی به‌صورت عادی دیده می‌شود؛ برای جابه‌جایی فضایی به Live Preview برگردید.

### کنترل‌ها

- `::`: جابه‌جایی؛ کلیدهای جهت ۱ پیکسل، همراه Shift برابر ۱۰ پیکسل.
- `↔`: تغییر عرض؛ کلیدهای چپ/راست هم پشتیبانی می‌شوند.
- Undo/redo متن حین ویرایش در محل: `Ctrl/Cmd+Z` و `Ctrl/Cmd+Shift+Z`؛ از history سند اصلی استفاده می‌شود.
- Undo مستقل چیدمان در این نسخه پیاده نشده است.
- اسکرول عمودی و افقی داخل همان ویرایشگر است. جای بلاک نسبت به فضای نوت ذخیره می‌شود، نه viewport. جای‌گذاری مطلق است، نه چیدمان واکنش‌گرای خودکار.

## نصب دستی

۱. از vault و تنظیمات پلاگین بک‌آپ بگیرید.
۲. سه فایل `main.js`، `manifest.json` و `styles.css` را از **همین شاخهٔ v0.2** در این مسیر بگذارید؛ یا پوشهٔ ZIP نصب را در مسیر plugins استخراج کنید:

```text
YourVault/.obsidian/plugins/canvesidian/
├── main.js
├── manifest.json
└── styles.css
```

۳. Obsidian را reload و Canvesidian را در Community plugins فعال کنید. برای اجرای پلاگین محلی Restricted mode باید خاموش باشد؛ تنها کدی را نصب کنید که به آن اعتماد دارید.
۴. یک نوت را در Live Preview باز و رفتار بالا را امتحان کنید. نسخهٔ هدف manifest برابر Obsidian 1.8+ است؛ سازگاری نسخه‌ها هنوز در اپ واقعی تأیید نشده است.

نسخهٔ ۰.۱ را هم‌زمان نصب نکنید؛ plugin ID یکسان است. با جایگزینی سه فایل، کد قدیمی عوض می‌شود. ابتدا بوردهای نسخهٔ قدیمی را ببندید و برنامه را reload کنید. دادهٔ بورد قدیمی هنگام مهاجرت زیر `legacyBoards` نگه داشته می‌شود، اما به بلاک‌های جدید تبدیل یا نمایش داده نمی‌شود. برای برگشت به v0.1 باید بک‌آپ قبلیِ `data.json` و فایل‌های همان نسخه را برگردانید.

## بلاک و اتصال به منبع

- واحد فعلی، **بلاک سطح اول Markdown** است: پاراگراف چندخطی، تیتر، تصویر مستقل، fenced code، لیست کامل، نقل‌قول کامل یا جدول GFM. این‌ها از syntax tree مستقل `@lezer/markdown` گرفته می‌شوند؛ از تیتر برای ساخت کارت‌های بزرگ استفاده نمی‌شود.
- هنوز یک کلمهٔ داخل پاراگراف، سلول جدول، آیتمِ داخل لیست تو‌در‌تو، یا هر DOM element دلخواه قابل جداکردن نیست. Frontmatter شناور نمی‌شود.
- ویرایش در محل یک textarea با Markdown خام است، نه نمونهٔ دوم Live Preview؛ autocomplete، commandهای همهٔ پلاگین‌ها و embedهای قابل‌ویرایش داخل آن تضمین نشده‌اند. هنگام پایان ویرایش، `MarkdownRenderer` میزبان برای نمایش استفاده می‌شود.
- نمایش اصلی بازهٔ شناور با decoration پنهان می‌شود، نه حذف از سند. `StateField` موقعیت بازه را با transactionهای متن map می‌کند؛ یک لایهٔ کوچک در `scrollDOM` همان ویرایشگر بلاک را نمایش می‌دهد.
- چیدمان در `.obsidian/plugins/canvesidian/data.json` ذخیره می‌شود. Markdown برای افزودن ID یا مختصات تغییر نمی‌کند. برای بک‌آپ جای بلاک‌ها، این فایل را نیز نگه دارید.
- پس از بازکردن مجدد، متن دقیق و زمینهٔ اطرافش برای شناسایی بلاک استفاده می‌شوند. این روش **شناسهٔ معنایی دائمی نیست**: اگر متن هنگام بسته‌بودن برنامه تغییر کرده یا تطبیق مبهم باشد، پلاگین آن را پنهان نمی‌کند و placement جداشده را نگه می‌دارد. برای محکم‌ترشدن این بخش، شناسهٔ پایدار opt-in مرحلهٔ بعد است.
- هم‌زمانیِ دو دستگاه یا دو pane برای چیدمان حل نشده است؛ تغییرات ذخیره‌شده می‌توانند last-writer-wins باشند. تایپ در نسخه‌های باز از طریق رفتار خود Obsidian انجام می‌شود، اما این پلاگین سیستم همکاری یا merge مجزا ندارد.

## حفظ پیش‌نویس و فارسی

- رویدادهای composition پشتیبانی شده‌اند: متن در حال ترکیب به‌صورت نیمه‌کاره به سند dispatch نمی‌شود.
- اگر هنگام ترکیب متن، منبع همان بلاک تغییر کند، پیش‌نویس روی متن جدید نوشته نمی‌شود؛ هشدار در محل ظاهر می‌شود و پیش‌نویس برای کپی باقی می‌ماند.
- اگر بلاک با یک پیش‌نویس اعمال‌نشده بسته/برگردانده شود، نسخهٔ بازیابی در `recoveryDrafts` ذخیره می‌شود. فرمان بازیابی بالا پنجره‌ای فقط برای خواندن/کپی باز می‌کند؛ نوت جدیدی نمی‌سازد و چیزی را خودکار روی متن اصلی نمی‌نویسد.
- این حفاظت، تضمین در برابر crash، خاموشی ناگهانی یا شکست ذخیره نیست. ذخیرهٔ دادهٔ چیدمان debounce شده است؛ قبل از اتکا به آن، بک‌آپ بگیرید.
- متن و متن بازیابی‌شده دادهٔ خصوصی vault هستند. کد پلاگین analytics یا درخواست شبکه ندارد؛ renderer و افزونه‌های دیگر می‌توانند رفتار خودشان را داشته باشند.

## مرزهای نمونهٔ اثباتی

- فقط ادغام در **Live Preview**؛ Reading View و PDF export چیدمان فضایی را نمایش نمی‌دهند. با غیرفعال‌کردن پلاگین، Markdown به شکل عادی قابل‌استفاده است.
- در این نسخه استیکر، ضمیمه، گروه‌بندی، انتخاب چندتایی، snap-to-grid، zoom، drag فایل از Finder، ایجاد باکس جدید با دوبارکلیک فضای خالی و undo چیدمان پیاده نشده‌اند. هدف اول، جابه‌جایی و ویرایش **بلاک موجود در همان نوت** است.
- هم‌پوشانی آزاد است؛ جلوگیری از برخورد با محتوای عادی یا بلاک دیگر وجود ندارد. فضای خالی برای اسکرول رزرو می‌شود؛ canvas واقعاً بی‌نهایت نیست. مختصات تا ۵۰٬۰۰۰ پیکسل و عرض بین ۲۰۰ و ۱۲۰۰ پیکسل محدودند.
- Parser مستقل ممکن است با بعضی syntaxهای اختصاصی Obsidian یا افزونه‌ها کاملاً منطبق نباشد. جدول، callout، embed پیچیده، selection، folding، undo در لبه‌ها و viewport virtualization واقعی میزبان نیازمند تست دستی‌اند.
- تست viewport باریک انجام شده، نه تست لمس و کیبورد روی گوشی واقعی. برای موبایل هنوز ادعای آمادگی نداریم.

## توسعه و اجرای تست

```sh
npm ci
npm run check
# Real CodeMirror UI harness, with mocked Obsidian host/renderer:
npm exec -- playwright install chromium
npm run test:ui
# Or reuse an installed Chromium:
CHROMIUM_PATH=/path/to/chromium npm run test:ui
```

- `src/main.ts`: ثبت extension و فرمان‌ها در ویرایشگر عادی؛ بدون `registerView` یا ساخت فایل.
- `src/spatial.ts`: StateField، map بازه‌ها، لایهٔ درون ویرایشگر، drag/resize، ویرایش در محل، lifecycle و پیش‌نویس بازیابی.
- `src/model.ts`: parser سطح اول، snapshot زمینه، تطبیق محافظه‌کارانه و مهاجرت داده.
- `tests/model.test.ts`: ۱۹ تست مدل.
- `qa/`: ۲۲ بررسی تعامل در Chromium با **CodeMirror واقعی** و mock API/renderer ابسیدین؛ شامل hover-to-drag، ویرایش اصلی، undo/redo، اسکرول، بازکردن مجدد از JSON، تغییر کامل سند، composition، conflict و recovery.
- CodeMirror در build تولیدی external است تا پلاگین نمونهٔ دومِ state/view را وارد Obsidian نکند؛ `@lezer/markdown` برای parsing مستقل bundle می‌شود.
- اسکرین‌شات‌های QA، محیط تست‌اند، نه تصویر اجرای واقعی Obsidian. harness عمداً Live Preview واقعی Obsidian را شبیه‌سازی نمی‌کند.

### تست دستی لازم پیش از انتشار

1. نصب در Obsidian واقعی؛ نوت در همان تب بماند و دستگیره در تم‌های مختلف درست ظاهر شود.
2. کشیدن پاراگراف، تصویر محلی، fenced code، جدول، لیست و callout بدون نمایش دو نسخه یا تداخل decorationهای میزبان.
3. ویرایش فارسی با IME واقعی، undo/redo، source-mode toggle، restart، تغییر نام فایل و چند pane.
4. متن طولانی و نوت بزرگ، لینک داخلی، embed، folding و سازگاری با افزونه‌های نصب‌شده.
5. بک‌آپ/restore `data.json` و آزمایش سناریوهای قطع ذخیره/تداخل sync.
