# Canvesidian

**نوت، یک فضای فکرکردن است؛ نه فقط یک ستون متن.**

An experimental Obsidian plugin that turns one Markdown note into a spatial workspace. Place sections freely, resize them, and attach emoji stickers or text notes. Attachments use coordinates inside their parent section: moving the section or scrolling the board carries them along. They are not fixed overlays on the viewport.

## وضعیت نسخهٔ ۰.۱.۰

این نسخه یک MVP قابل ساخت و نصب دستی است؛ هنوز داخل اپ واقعی Obsidian تأیید نشده و در Community Plugins منتشر نشده است. ابتدا روی یک vault آزمایشی یا با بک‌آپ تست کنید.

### چه کار می‌کند؟

- هر تیتر ATX از `#` تا `######` یک بخش مستقل می‌سازد؛ محتوای قبل از اولین تیتر هم یک بخش است. نوت بدون تیتر یک قطعه دارد.
- بخش‌ها را با دستگیرهٔ `::` بکشید و در فضای دوبعدی قرار دهید؛ از گوشهٔ پایین عرض را تغییر دهید. ارتفاع با محتوا تنظیم می‌شود.
- دکمهٔ `＋` روی هر بخش، ایموجی یا یادداشت متنی اضافه می‌کند. ضمیمه در ابتدا زیر بخش قرار می‌گیرد؛ می‌توانید آن را روی بخش یا اطرافش بکشید. مختصاتش همواره نسبت به همان بخش است.
- ضمیمه‌ها همراه بخش حرکت می‌کنند و همراه محتوای بورد اسکرول می‌شوند. چسبیدن در این نسخه به **بخش** است، نه یک کلمه یا پاراگراف خاص.
- `Edit` متن Markdown همان بخش را در پنجرهٔ جدا باز می‌کند؛ ذخیره در فایل اصلی انجام می‌شود. اگر فایل در این فاصله تغییر کند، ذخیره متوقف می‌شود و پیش‌نویس در پنجره باقی می‌ماند تا آن را کپی کنید.
- `Undo layout` تا ۴۰ تغییر چیدمان/ضمیمه را در همان نشست برمی‌گرداند؛ ویرایش متن فایل را undo نمی‌کند.
- `Tidy` بخش‌ها را در شبکه می‌چیند. `Home` به ابتدای فضا می‌رود. برای جابه‌جایی در فضا از اسکرول عمودی و افقی استفاده کنید.
- دستگیره‌ها با کلیدهای جهت هم کار می‌کنند: ۱ پیکسل، یا همراه Shift برابر ۱۰ پیکسل.
- متن فارسی با جهت خودکار و رنگ‌ها مطابق تم Obsidian نمایش داده می‌شوند.

## نصب دستی

۱. ابتدا از vault بک‌آپ بگیرید.
۲. فایل‌های `main.js`، `manifest.json` و `styles.css` را از همین شاخه بردارید، یا از سورس بسازید:

```sh
npm ci
npm run check
```

۳. این ساختار را داخل vault ایجاد کنید:

```text
YourVault/
└── .obsidian/
    └── plugins/
        └── canvesidian/
            ├── main.js
            ├── manifest.json
            └── styles.css
```

۴. Obsidian را reload کنید و پلاگین **Canvesidian** را از بخش Community plugins فعال کنید. فعال‌کردن پلاگین محلی نیازمند خاموش‌بودن Restricted mode است؛ فقط کدی را نصب کنید که به آن اعتماد دارید.
۵. یک نوت Markdown باز کنید. از Command Palette فرمان `Canvesidian: Open current note as a freeform board` را اجرا کنید. آیکون ribbon و منوی راست‌کلیک فایل هم همین نما را باز می‌کنند.

برای حذف، پلاگین را غیرفعال و پوشه‌اش را حذف کنید. متن Markdown به جای خود باقی می‌ماند؛ حذف پوشه، چیدمان و ضمیمه‌ها را نیز پاک می‌کند.

## داده و حفظ محتوا

- متن، لینک‌ها و تیترها در همان فایل `.md` می‌مانند. جابه‌جایی، استیکر و تغییر عرض، فایل اصلی را بازنویسی نمی‌کنند؛ فقط `Edit → Save` متن را تغییر می‌دهد.
- چیدمان و متن ضمیمه‌ها در `.obsidian/plugins/canvesidian/data.json` با `version: 1` ذخیره می‌شوند. برای بک‌آپ ضمیمه‌ها این فایل را هم نگه دارید. همگام‌شدن آن به تنظیمات sync پوشهٔ پلاگین‌های شما وابسته است.
- هیچ analytics، درخواست شبکه یا سرویس خارجی در کد پلاگین وجود ندارد. نمایش Markdown از renderer خود Obsidian استفاده می‌کند؛ محتوای نوت و سایر افزونه‌های نصب‌شده ممکن است رفتار خودشان را داشته باشند.
- شناسهٔ بخش فعلاً از سطح تیتر، متن تیتر و شمارهٔ تکرار آن ساخته می‌شود. تغییر بدنه چیدمان را نگه می‌دارد. تغییر نام تیتر، تغییر سطح آن، یا جابه‌جایی تیترهای هم‌نام ممکن است اتصال را تغییر دهد.
- چیدمان بخش ناپدیدشده حذف نمی‌شود. هشدار `detached layouts` و فرمان `Recover attachments` ضمیمه‌های جداشده را به اولین بخش موجود منتقل می‌کند. این بازیابی هوشمندِ مقصد نیست.
- تغییر نام/مسیر فایل در همان vault چیدمان را منتقل می‌کند. حذف فایل دادهٔ چیدمان را برای بازیابی احتمالی نگه می‌دارد. انتقال بین دو vault و merge هم‌زمان `data.json` پشتیبانی نشده است.

## مرزهای این MVP

- نمای مستقل است، نه دست‌کاری Live Preview و نه جایگزین Obsidian Canvas.
- کارت‌ها برای خواندن، ویرایش متن در modal؛ ویرایش مستقیم و هم‌زمان داخل کارت‌ها وجود ندارد.
- فقط تیترهای ATX؛ تیترهای Setext با `===` و `---` جداکنندهٔ بخش نیستند. کامنت‌های YAML frontmatter و تیترهای داخل fenced code blocks جدا نمی‌شوند. این یک parser کامل CommonMark نیست؛ تیترهای داخل ساختارهای پیچیده مثل HTML خام ممکن است درست تفکیک نشوند.
- استیکر فعلاً ایموجی/متن است، نه آپلود عکس. متن کوتاه تا ۸ واحد UTF-16 با ظاهر استیکر نمایش داده می‌شود؛ متن بلندتر با ظاهر یادداشت.
- ضمیمه به مختصات بخش متصل است، نه موقعیت معنایی یک جمله؛ افزایش متن ممکن است نیاز به جابه‌جایی دستی ضمیمه داشته باشد.
- چیدمان عمداً امکان هم‌پوشانی دارد؛ موتور جلوگیری از برخورد، zoom، اتصال خطی، گروه‌بندی، nested sections، undo متن، clipboard تصویری و همکاری هم‌زمان هنوز وجود ندارد.
- مختصات مثبت تا ۵۰٬۰۰۰ پیکسل و عرض ۲۴۰ تا ۱۲۰۰ پیکسل محدود شده‌اند؛ این فضای بزرگ است، نه canvas بی‌نهایت واقعی.
- بورد در عرض کم با اسکرول افقی استفاده می‌شود. تست viewport باریک انجام شده، نه تست روی دستگاه واقعی موبایل.

## توسعه و تست

```sh
npm ci
npm run check
# Optional UI harness; installs a local test browser:
npm exec playwright install chromium
npm run test:ui
# Or reuse an installed Chromium:
CHROMIUM_PATH=/path/to/chromium npm run test:ui
```

- `src/model.ts`: تجزیهٔ محدوده‌های متن، حفظ بایت‌های خارج از ویرایش، کنترل تداخل، چیدمان و بازیابی دادهٔ ذخیره‌شده.
- `src/main.ts`: نمای Obsidian، چرخهٔ render، drag/resize، ویرایش و ذخیره.
- `tests/model.test.ts`: ۱۳ تست مدل برای CRLF، فارسی، fenced code، تیتر تکراری، حفظ متن، conflict، frontmatter و بازیابی ضمیمه.
- `qa/`: اجرای **کد واقعی پلاگین** با یک mock کوچک API ابسیدین و renderer سادهٔ متنی در Chromium. ۱۲ بررسی شامل حرکت، اسکرول، ضمیمه، resize، ویرایش، conflict، undo و viewport باریک. این تست، صحت renderer واقعی یا اجرای اپ Obsidian را ثابت نمی‌کند.
- `main.js` خروجی build برای نصب مستقیم است؛ پس از تغییر سورس آن را دوباره بسازید.
- CI بررسی typecheck، تست مدل و build را اجرا می‌کند و سه فایل نصب را به‌عنوان artifact می‌دهد. اجرای CI به تنظیمات GitHub Actions ریپو وابسته است.

### تست دستی لازم پیش از انتشار

- نصب در Obsidian دسکتاپ و موبایل، بازوبسته‌شدن بورد و restart برنامه.
- لینک داخلی، embed، تصویر، جدول، کد و callout با renderer واقعی.
- تغییر فایل از ویرایشگر عادی در کنار بورد، rename/delete، نام‌های تکراری و تغییر تیترها.
- تم روشن/تیره، لمس، نوت‌های بسیار بزرگ و تداخل با پلاگین‌های دیگر.
- بک‌آپ/restore فایل `data.json` و رفتار sync در vault واقعی.

## مسیر بعدی پیشنهادی

۱. شناسهٔ پایدار و opt-in برای هر بلوک؛ ۲. اتصال ضمیمه به پاراگراف؛ ۳. پَن/زوم؛ ۴. ویرایش inline؛ ۵. استیکر تصویری و گروه‌بندی. هیچ‌کدام در این نسخه پیاده‌سازی نشده‌اند.
